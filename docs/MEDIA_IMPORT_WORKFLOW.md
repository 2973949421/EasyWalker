# ADV Walkman 媒体导入工作流

本流程服务用户私有、非商用曲库。设备端仍只消费准备好的MP3、LRC和ADV封面，不在ESP32上访问网络API。

## 输入方式

后续用户可以提供：

1. 本地音频目录；或
2. 只有“歌曲名／艺人”的歌单。

本地文件优先。读取M4A/MP4标签时同时检查音频、内嵌封面和`lyrics`标签；原始文件保持不动。

## 两类API

### 曲源与候选元数据：GD音乐台

- 来源：`music.gdstudio.xyz`，使用时注明“GD音乐台(music.gdstudio.xyz)”。
- 遵守其CC BY-NC 4.0、仅学习参考、不得传播或商用的说明。
- 搜索接口用于取得track ID、正式标题、艺人、专辑、歌词ID和封面ID。
- 用户明确要求为私有学习曲库取音频时才使用`types=url`；已有用户音频时不调用。
- 粤语优先试`joox`，其他来源按可用性选择；5分钟内严格少于50次请求。
- 搜索可能返回无关同艺人热门歌，也可能503，因此不能单独自动判定。

### 同步歌词：LRCLIB

- 文档：`https://lrclib.net/docs`。
- 首选`/api/get`，传入正式标题、艺人、专辑和精确时长；LRCLIB按约±2秒匹配。
- 精确签名404时才用`/api/search`找候选，再按标题、艺人、版本和时长过滤。
- 客户端请求携带明确`User-Agent`；批量请求顺序发送，间隔200–500ms，并服从429的`Retry-After`。
- 只采用有`syncedLyrics`且录音版本吻合的记录。Live、Remaster、翻唱或时长不符不得自动套用。

## 匹配和文字规则

- Title和Artist最终以官方发行信息为准；方便命名的本地文件名不作为显示标题。
- 内嵌歌词可作为文字校对真源，但普通M4A的`lyrics`通常没有时间戳，不能直接驱动播放器同步。
- 有可靠同步源时可借用时间轴，同时保留用户文件中的正确繁体、粤语字和分句；首句、段落转换和尾句要抽查。
- 粤语：保留原始简繁，一列显示，不另造简体翻译列。
- 日文、俄文等：保留原文时间轴，另做自然中文翻译；译文时间戳必须与原文对应，不直接采用未经审阅的机器翻译。
- 找不到同步歌词时标记为`NO_SYNC_LYRICS`，不伪造平均时间轴；自动语音对齐只能生成待人工抽查的候选。

## 设备包

```text
Music/<曲库>/<正式歌名>.mp3
Lyrics/<曲库>/<正式歌名>.lrc
ADVWalkman/covers/<曲库>/<正式歌名>.cover.adv
```

- MP3为320kbps、44.1kHz、双声道，不做响度归一化。
- MP3 Title/Artist写正式名称；文件系统允许时文件名也使用正式歌名。
- 内嵌JPEG先提取原图，再生成135×135、40×32字符的设备封面。
- 生成manifest记录源文件Hash、输出Hash、时长、歌词提示数和时间轴来源。
- SD插入后才执行明确的受管文件同步；不得清理无关音乐、状态或日志。
